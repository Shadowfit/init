## DB 축 (§5-2) — 로컬 표가 333행이라 **EXPLAIN 만**, 시간·크기 셀은 미수행

행당 JSON 은 **4,110~4,145B** — 합성 rig(`pose_data_scale`)의 2.3KB 보다 1.8배 크다(실제 float 정밀도). 크기 셀(100/1k/10k 행)·cold/warm 은 합성 rig 가 로컬에 없어 안 돌렸다 — 돌릴 때는 행 크기를 4.1KB 로 맞춰야 한다.

## 정직하게

1. 스톡 영상 6세션 239행. 실사용자도 이 앱의 셀피 파이프라인도 아니다 — «실사용에서 23% 갈린다» 는 말 금지. 10월 사용자 테스트 데이터로 같은 스크립트를 다시 돌린다.
2. 3D/2D 어느 쪽이 맞는지는 못 정한다. 이 측정이 정하는 것은 «자를 바꾸면 카운트가 흔들린다(3/6)» 까지다.
3. «가림이 원인» 가설은 기각에 가깝다 — 보이는 무릎도 갈린다. 다만 가려진 무릎의 폭이 더 큰 것은 맞다.
4. 각도 수식은 SQL 사본이다. 저장값과 0.01° 로 맞았지만, 실시간 판정은 여전히 `angle_calculator.py` 다.
