# 센 반복만 채점하면 리포트가 좋게만 나온다 — «인정 반복» 과 «채점 시도» 분리 (2026-10-21)

> 분기점 문서다. 2026-10-21 최종 사용자 결정은 §6 — «2번»(= 후보 A, 인정 각도는 원래 115°·두 표본 그대로). 같은 날 먼저 적용한 «1번» 은 되돌렸다(§6-1).

## 1. 문제

사용자 지적: «자세가 안 좋으면 카운팅 자체가 안 된다. 좋은 자세만 세니 리포트는 무조건 좋게 나온다.»

리포트의 모든 점수(싱크로율·깊이·체간)는 **AI 가 1회로 센 반복만** 재료로 쓴다. 세지 않은 시도는 AI 안에서
버려지고 Spring 에 아무것도 가지 않는다 — 리포트·DB·서버 로그 어디에도 흔적이 없다(앱 화면에 잠깐 뜨는 안내뿐).

## 2. 확인한 사실 (실촬영 좌표 기록 4개를 실제 `SquatCounter` 로 재생)

| 기록 | 센 횟수 | 버린 시도 | 비고 |
|---|---|---|---|
| squat_normal_01 | 5 | 0 | 점수 86~90 |
| squat_normal_02 | 5 | 0 | 무릎 76~93°, 점수 **47~86** — 센 반복도 낮게 나온다 |
| squat_side_01 | 5 | 0 | 점수 89~95 |
| squat_shallow_01 | **0** | 5 | 무릎 90~112° 까지 내려갔는데 0회 |

shallow 기록을 프레임 단위로 보면 다섯 시도가 버려진 이유는 **자세가 아니었다**:

- **앞의 3회 — 준비 자세 인식 실패.** 처음 «서 있다» 로 인정하려면 고관절 각도 150° 이상이 필요한데 이 사람은
  140~147° 로 서 있었다. 4초 동안 `waiting_for_standing` 에 머물러 무릎 95°·90°·104° 시도를 통째로 무시했다.
- **뒤의 2회 — 바닥을 한 장만 봤다.** 바닥 조건(무릎 ≤ 115°·고관절 ≤ 150°·골반 하강 ≥ 몸통 0.25)을 다 만족한
  프레임(무릎 101.5°)이 있었지만, 바닥은 **연속 두 프레임**에서 확인돼야 한다(`bottom_confirm_sec` 0.12초). 앱이
  초당 약 3장이라 빠른 반복은 바닥이 한 장에만 찍힌다. 선 자세 확인은 이미 «표본 간격이 확인 시간보다 길면 한 장으로
  인정» 하는데(2026-09-21) 바닥 확인엔 그 규칙이 없다.
- 같은 식으로 채점했다면 버린 시도는 46·39점이었다 — 리포트에 들어갔다면 평균을 끌어내렸을 값이다.

바닥 확인에 선 자세와 같은 규칙을 적용하면: 정상 기록 3개는 5·5·5회 그대로, shallow 는 0 → 2회(나머지 3회는 준비 자세 문제).

**오늘(10-21) 이미 바뀐 것** — 센 반복 안에서는 이제 점수가 갈린다. 깊이 점수 만점은 «시범 최저 무릎 + 5° = 76°» 이고
1° 당 4점 감점이라, 115° 문턱 안쪽의 얕은 반복(무릎 93°)은 깊이 32점·싱크로율 47점이다. 그래서 «무조건 100점» 은
센 반복에 대해선 더 이상 사실이 아니다. 남은 구멍은 **세지 않은 시도가 리포트에 안 보이는 것** 이다.

## 3. 카운트 문턱 자체 — 얼마나 내려가야 1회인가

`bottom_knee 100 + margin 15 = 115°` 이하·고관절 ≤ 150°·골반 하강 ≥ 몸통 길이 0.25. 근거는 Sousa et al.(2026) Listing 1
과 2D 잡음 여유(`docs/decisions/squat-repetition-counting.md`). «얼마나 앉아야 1회로 인정하나» 는 운동 규칙(크로스핏의
no-rep 처럼)이라 문턱이 있는 것 자체는 정상이다. 문제는 **문턱에 못 미친 시도를 기록하지 않는 것**이다.

## 4. 후보

### A. 시도 단위로 기록 — 횟수는 «인정 반복», 점수는 «모든 시도» (추천)

- AI: 내려갔다 올라온 시도(지금 «충분히 내려간 장면을 확인하지 못했어요» 를 띄우는 자리)를 반복과 같은 방식으로
  채점해 Spring 에 보낸다. 사유 코드: 깊이 부족 · 런지 자세 · (필요하면) 너무 짧음.
- proto: `PoseDataRequest` 에 `counted`(bool)·`attempt_number`·`reject_reason` 추가 — 추가만 하므로 한쪽만 배포돼도 안 깨진다.
- DB: `pose_data` 에 같은 세 컬럼(V35). 기존 행은 전부 `counted = true`.
- Spring: 횟수·세트 진행·목표 달성은 지금처럼 인정 반복만. 리포트 점수(평균 싱크로율·깊이·체간)는 **모든 시도**로 계산.
  응답에 `attemptCount`·`notCountedCount`·사유별 개수.
- 앱: 요약에 «인정 9회 · 미인정 2회(깊이 부족)», 회차별 막대에 미인정 시도를 회색 «미인정» 으로, 코칭 카드에
  «2회는 깊이가 부족해 인정되지 않았어요».
- 트레이드오프: 평균 싱크로율의 의미가 바뀐다(«센 반복 평균» → «시도 평균») — 이전 세션과의 비교가 한동안 어긋난다.
  pose_data 행이 조금 는다(시도당 1~2행, 다운샘플 후).

### B. 내려갔다 올라오면 전부 1회로 센다 — 점수로만 구분

- 가장 단순하다(문턱을 «시도 인식» 수준으로 낮춤). 대신 횟수·세트·목표가 의미를 잃는다(살짝 무릎만 굽혀도 1회).

### C. 미인정 시도 «개수» 만 리포트에 보여준다

- 변경이 가장 작다(AI 가 개수와 사유만 세션 완료 때 보냄). 점수는 여전히 센 반복만이라 «좋게만 나오는» 문제는 남는다.

### 후보와 상관없이 고칠 것 (카운트 신뢰성 버그)

1. 바닥 확인을 선 자세와 같은 규칙으로 — 표본 간격 ≥ 0.12초면 바닥 한 장으로 인정. 정상 기록 횟수 불변 확인.
2. 준비 자세 인식 — 고관절 150° 요구 때문에 살짝 숙여 서는 사람은 시작이 안 된다. 무릎 기준 + 정지 시간으로 완화할지 검토.
3. (선택) 전송 속도 3fps → 5fps — 바닥을 놓치는 빈도가 준다. 서버 부하가 늘어 별도 측정이 필요하다(`ai-load-budget.md`).

## 5. 결정할 것

1. A·B·C 중 무엇으로 할지.
2. A 라면: 리포트 «평균 싱크로율» 에 미인정 시도를 포함할지(추천: 포함, 화면에 «시도 N회 기준» 표기).
3. 카운트 문턱 115° 를 유지할지(추천: 유지 — 문턱은 운동 규칙이고, 미달은 A 로 드러난다).

## 6. 결정 (2026-10-21, 최종) — «2번»: 횟수는 원래 규칙, 미인정 시도를 세어 보여주고 리포트에 반영

**최종 결정은 2번이다.** 아래 «1번» 을 같은 날 먼저 적용했다가, 사람 판정과의 충돌(아래 ⚠️)을 확인하고 되돌렸다.
사용자 정리: «정상 카운팅뿐 아니라 미인정 카운팅도 되는 게 맞다. 사용자도 알아야 한다.»

- **횟수(세트·목표의 기준)**: 원래 규칙 그대로 — 무릎 ≤ 115°·고관절 ≤ 150°·골반 하강 ≥ 몸통 0.25 인 바닥 자세가 **연속 두 표본**에
  찍혀야 1회. 처음 선 자세 인정 고관절 150°(`initial_hip_margin` 10). 사람 판정과 4개 실촬영 모두 일치(normal 5·5·side 5·shallow 0).
- **미인정 시도**: 내려갔다 올라왔지만 위 조건을 못 채운 «진짜 시도»(활동 ≥ 0.4초·골반 하강 ≥ 몸통 0.25 — 기존 «충분히 내려간 장면을
  확인하지 못했어요» 판정)와 런지 자세로 버린 시도. 추적 끊김·발 이동·오래 앉음은 시도가 아니다.
  - 운동 중: 화면에 «인정 N회 · 미인정 M» 과 안내 문구, 진동. AI `PoseResponse.rejected_count`·`rejected_reason`.
  - 저장: 인정 반복과 같은 식으로 싱크로율을 매겨 AI → Spring `SaveRejectedAttempt`(새 RPC) → `exercise_rejected_attempts`(V35).
  - 리포트: 미인정 수·사유, 회차 막대에 회색 ✕, 평균 싱크로율·깊이·체간 점수에 포함(«모든 시도» 평균), 코칭 카드에 한 줄.
  - 이어하기: `ReattachRequest.initial_rejected_count` 로 화면 카운트가 이어진다.
- 실촬영 shallow_01: 인정 0회, 미인정 2회(선 자세 인식 전의 3회는 시도로도 안 잡힌다 — 촬영 규약 «시작 2초 정지» 미충족).

### 6-1. 먼저 적용했다가 되돌린 «1번» (기록)

사용자와 정리한 두 정책 중 처음엔 «1번» 을 택했다.

- **1번**: 인정 기준 115° 그대로. 바닥 한 장 확인·준비 자세 고관절 140° 로 고쳐, 115° 안쪽의 얕은 반복은 **세어서 낮게 채점**한다.
- 2번(= 후보 A + 인정 각도 명시): 기준 미달은 세지 않고 «미인정» 으로 리포트에만 보인다. 범위가 크다(proto·DB·Spring·앱).

적용(AI 만): `squat_counter`(바닥 `dt ≥ bottom_confirm_sec` 이면 한 장 확정, `initial_hip_margin` 10 → 20),
`squat_analyzer`·`reference_builder`(«내려가는 중·바닥» 을 함께 시도 시작으로). 결과(실촬영 재생): normal_01·02·side_01 5·5·5회 그대로,
shallow_01 0 → **4회**.

⚠️ **사람 판정과의 충돌 — 결정 후 확인한 사실.** `docs/verification/2026-09-21-verification-report.md` 는 shallow_01 을 사람이 «얕은 시도
5회 · 정상 0회» 로 판정했고, 그때 바닥 한 장 확정을 시도했다가 «경계에 한 장만 닿은 애매한 반복을 세 버린다» 는 이유로 되돌렸다. 45° 촬영의
2D 무릎각은 사람이 «얕다» 고 본 시도를 90~112° 로 읽는다(정상 판정 normal_02 1회차가 93° 라 각도만으로는 두 판정이 겹친다). 그래서 1번은
**횟수가 사람 판정보다 후하다** — 이 영상 4회 vs 사람 0회. 대신 그 4회는 깊이 0~45점·싱크로율 39~46% 로 리포트에 낮게 나온다.
횟수까지 사람 판정에 맞추려면 2번(115°·두 장 확인을 유지하고 미달 시도를 «미인정» 으로 기록)이 맞다 — 사용자 재확인 후 2번으로 바꿨다(위 §6).
