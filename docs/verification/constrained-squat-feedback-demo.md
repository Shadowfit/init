# 고정 촬영 조건 스쿼트 피드백 시연 기준

작성: 2026-09-18. 목표는 **고정된 촬영 조건과 미리 정한 시험 영상**에서의 동작·피드백 일치다. 모든 장소와 사람에 대한 자세 판정 정확도를 뜻하지 않는다.

## 촬영 조건

- 한 사람, 한 카메라 위치, 45도 정면 방향. 카메라를 고정하고 머리부터 발목까지 여백을 두고 담는다.
- 조명이 충분하고 무릎·골반·발목을 가리는 랙이나 기구가 없다. 영상 중 카메라와 발 위치를 옮기지 않는다.
- 매 영상의 앞뒤에 서 있는 자세를 2초 이상 담는다. 화면 속 몸 방향과 카메라 위치를 영상마다 같게 유지한다.
- 앱 기본 분석 속도인 3fps로 평가한다. 이 조건을 못 채운 프레임은 횟수·자세의 정답으로 취급하지 않고 촬영 안내를 표시한다.

## 현재 구현한 화면 안내

- 깊은 자세까지 추적한 뒤 다시 서면 `스쿼트 깊이를 확인하고 1회 기록했어요.`를 한 번 보낸다.
- 골반은 내려갔지만 카운터가 하단 자세를 확인하지 못한 채 다시 서면 횟수를 늘리지 않고 `이번 동작에서 충분히 내려간 장면을 확인하지 못했어요.`를 한 번 보낸다. 이 문장은 **관찰 결과**이며, 운동자가 실제로 얕게 했다고 단정하지 않는다.
- 관절이 가려지면 기존 `LOW_VISIBILITY` 촬영 안내를 사용한다. 상체 기울기를 `등 굽음`이나 부상 위험으로 해석하는 피드백은 이번 시연의 성공 조건에 포함하지 않는다.

이 피드백은 논문의 각도 기반 주기 판정에서 출발하지만, 골반 하강 여유값과 문구는 구현 선택이다. 임상적으로 검증된 자세 평가나 운동 종목 자동 분류가 아니다.

## 100% 합격의 뜻

촬영 전에 시험 영상 5개를 정한다: 정상 스쿼트 5회씩 3개, 일부러 깊이만 줄인 동작 5회 1개, 서 있거나 가볍게 자세만 바꾸는 20초 영상 1개. 각 동작의 **완료 또는 되돌아온 시각**과 `정상/깊이 미확인`을 사람이 기록한다. 첫 두 영상으로 촬영 조건만 점검한 뒤, 남은 영상으로 최종 평가한다. 판정값을 최종 영상에 맞춰 바꾸면 그 영상을 다시 독립 검증 자료라고 부르지 않는다.

합격은 분석 가능한 최종 영상에서 사람 라벨과 카운트·피드백 종류·발생 시각이 모두 일치하고, 추가 횟수나 추가 피드백이 0개이며, 앱 화면에 안내가 실제로 나타나는 경우다. `scripts/evaluate_squat.py --trace`의 `coaching_event` 열과 JSON의 `coaching_events`에서 이벤트 시각을 확인할 수 있다. 한 건이라도 다르면 100%라고 보고하지 않고 어떤 시점에서 누락 또는 오검출됐는지 기록한다.

현재 저장소 영상에서는 45도 정면·후면의 수동 횟수 2회씩은 모두 검출했지만, ROI 영상은 사용자가 센 7회 중 완결된 5회만 검출했다. ROI 영상은 첫 프레임부터 이미 앉는 중이고 마지막 기립 직후 끝나므로, 이 문서가 정한 앞뒤 2초 선 자세 조건을 충족하지 않는다. 따라서 **현재는 새 시험 영상에서의 100% 합격을 주장하지 않는다.** 촬영 조건이 정해진 새 영상이 필요하다.

## 현재 확인 결과

2026-09-18에 원본 영상에서 MediaPipe부터 다시 처리했다. 45도 정면은 22/22 프레임 사용 가능·2회·완료 안내 2건, 45도 후면은 23/25 프레임 사용 가능·2회·완료 안내 2건, ROI는 54/54 프레임 사용 가능·5회·완료 안내 5건이었다. 얕은 동작 안내 1건과 정상 동작 완료 안내 1건의 단발성은 합성 궤적 및 HTTP 응답 테스트로 확인했다.

2026-09-19에는 별도 MySQL·Spring·AI Docker 스택에서 회원가입부터 리포트까지 실제 API 경로를 실행했다.

| 영상 | 사람 라벨 | API 횟수 | 완료 안내 | 리포트 저장 | 결과 |
|---|---:|---:|---:|---:|---|
| 45도 정면 | 2 | 2 | 2 | 2 | 통과 |
| 45도 후면 | 2 | 2 | 2 | 2 | 통과 |
| ROI | 7 | 5 | 5 | 5 | 촬영 규약 미충족 |

ROI 추적표를 보면 0초의 무릎 각도가 약 120도로 이미 동작 중이고, 마지막에는 선 자세 표본이 한 장뿐이라 0.2초 복귀 확인을 할 수 없다. [첫 프레임](screenshots/roi-first-frame.jpg), [마지막 프레임](screenshots/roi-last-frame.jpg), [54개 표본 추적표](roi-squat-trace.csv)를 근거로 남겼다. 가운데 완결된 5회는 API와 리포트가 모두 5회로 일치했다. 이 결과는 촬영 앞뒤의 선 자세가 단순 권장사항이 아니라 판정 가능한 동작 경계를 만드는 조건임을 보여준다.

검사 프로그램이 중간 실패해도 세션 종료를 재시도하도록 고쳤고, 실패 세션 3개를 연속으로 만든 뒤 같은 AI 작업자에서 정상 영상 2회를 다시 처리해 통과했다. AI 검출기 풀이 찼을 때도 시작 성공처럼 남지 않고 백엔드가 실패 상태로 전환되는 것을 4개 동시 세션으로 확인했다. AI 테스트는 `test_camera.py` 제외 **200 passed, 61 subtests passed**, 백엔드는 Docker JDK 21에서 **857 tests, 0 failures, 0 errors, 17 skipped**, 프런트 TypeScript 검사와 Expo 웹 export는 통과했다. 실제 휴대전화 카메라 화면의 토스트와 새 시험 영상 5개는 아직 확인이 필요하다.

## 2026-09-21 갱신: 새 시험 영상 검증과 기립 확인 지연 수정

`squat_normal_01.mp4`·`squat_normal_02.mp4`·`squat_shallow_01.mp4`·`squat_negative_01.mp4`·`squat_front_01.mp4`·`squat_side_01.mp4` 6개를 받아 사람이 먼저 눈으로 확인(프레임 단위 캡처, 파일명이나 AI 결과에 의존하지 않음)한 뒤 `evaluate_squat.py`로 평가했다. 상세 방법·영상별 사람 판정·실패 원인·수정 내역은 [2026-09-21 검증 보고서](2026-09-21-verification-report.md)에 있다. 요약:

- `squat_normal_01.mp4`·`squat_normal_02.mp4`는 실제로 각 5회씩 정상 깊이 반복이었지만(눈으로만 본 1차 확인은 각각 4회·3회로 과소 판정 — 원본 각도 추적표로 정정), 정점에서 짧게만 서는 반복이 있어 기존 코드는 4회로 과소 계상했다. 원인은 기립 확인 지연(0.2초)이 3fps 표본 간격(약 0.33~0.4초)보다 짧아, 두 번째 표본이 오기 전에 확정할 방법이 없었기 때문이다. `squat_counter.py`의 기립 확인 로직을 표본 간격을 고려하도록 고친 뒤 두 영상 모두 5회로 정확히 일치했다 (근거: [수정 전](../2026-09-21/baseline/) / [수정 후](../2026-09-21/final/) trace).
- `squat_negative_01.mp4`는 22.26초 내내 스쿼트 없음을 확인했고 AI도 0회·오검출 0건으로 일치했다.
- `squat_shallow_01.mp4`는 촬영 규약(시작 2초 정지 자세)을 지키지 않아 사람이 본 5회 중 3회가 준비 자세 계산 완료 전에 일어나 AI가 아예 평가하지 못했고, 나머지 2회는 원본 각도상 경계선에 걸쳐 있어 완료로 계상하지 않는 것이 보수적으로 맞다고 판단했다. 깨끗한 얕은 동작 기각 시연을 위해서는 재촬영이 필요하다.
- `squat_front_01.mp4`(순수 정면, 협의된 45도 아님)는 사람이 5회 모두 확인했지만 3fps 표본이 실제 최저점을 자주 놓쳐 AI는 1회만 확정했다 — 확인 지연이 아니라 표본화 자체의 한계로, 이번에는 임계값을 낮추지 않고 한계로만 기록했다.
- `squat_side_01.mp4`(순수 측면, 협의된 45도 아님)는 1차 눈 검증에서 상체가 계속 앞으로 숙여져 있어 "반복 아님"으로 오판했으나, 원본 무릎 각도 추적표를 보면 무릎은 매 주기 55~178도 사이를 오가는 진짜 5회 반복이었다. 상체 숙임이 심한 자세 자체는 코칭 품질 관점에서 별도로 기록해 둔다.

수정 후 `normal_01`·`normal_02`는 이번 수정을 진단하는 데 쓴 영상이라 최종 홀드아웃으로 다시 쓰지 않는다(검증 유출). `negative_01`만 독립적인 최종 홀드아웃으로 인정한다. 45도 각도의 새 정상/얕은 영상 재촬영이 더 필요하다.

## 촬영자가 가져올 자료

아래 파일명으로 찍으면 결과를 바로 대조할 수 있다.

1. `squat_normal_01.mp4` — 정상 깊이 5회
2. `squat_normal_02.mp4` — 정상 깊이 5회
3. `squat_normal_03.mp4` — 정상 깊이 5회
4. `squat_shallow_01.mp4` — 의도적으로 깊이를 줄인 동작 5회
5. `squat_negative_01.mp4` — 20초간 서 있기와 가벼운 자세 변경, 스쿼트 0회

각 파일과 함께 실제 횟수, 얕게 수행한 동작의 완료 시각만 적는다. 프레임 번호는 나중에 자동으로 계산할 수 있으므로 사용자가 직접 매길 필요가 없다. 최종 세 영상은 임계값을 고친 뒤 재사용하지 않고 그대로 합격/불합격을 판정한다.

영상 파일을 `samples/validation`에 둔 뒤 [검증 명세 예시](constrained-squat-manifest.example.json)의 파일명과 기대값을 확인하고 아래 명령을 실행한다.

```powershell
$env:PYTHONPATH=(Resolve-Path 'ai-server').Path
ai-server/.venv/Scripts/python.exe ai-server/scripts/evaluate_constrained_squat_set.py `
  docs/verification/constrained-squat-manifest.example.json `
  --output docs/verification/constrained-squat-result.json
```

이 명령은 각 영상의 횟수, 완료 안내 수, 깊이 미확인 안내 수를 한꺼번에 비교하고 하나라도 다르면 종료 코드 1을 반환한다. 현재 저장소의 완결된 주기만 넣은 연기 시험 결과는 [3/3 통과](existing-squat-smoke-result.json)다. 최종 합격 때는 이 자동 결과와 프레임별 이벤트 시각을 함께 확인한다.
