# 정확도 검증 — 영상 24~32개로 «대략 이 정도 맞는다» 를 숫자로

README 가 «정확도 검증이 얕다» 고 적고 있다. 이 문서와 `ai-server/scripts/accuracy_report.py` 는 그 한 줄을 **숫자와 실패 사례**로 바꾸는 최소 절차다.

> **이 검증이 말해 주는 것과 못 해 주는 것**
> - ✅ «이 영상들에서 rep 수가 평균 몇 개 틀리는가», «나쁜 자세를 몇 % 잡아내는가» — 그리고 어떤 조건(각도·조명)에서 틀리는가.
> - ❌ 일반적 정확도가 아니다. 영상 24~32개는 표본이 작아 비율의 95% 구간이 넓다(예: 30개 중 26개 맞음 = 87%, 구간 약 70~95%). 스크립트가 구간을 같이 낸다 — **«87%» 가 아니라 «87%(구간 70~95%, n=30)» 로 적을 것.**
> - ❌ 사람 라벨이 정답이라는 보장이 없다. 같은 영상을 두 사람이 따로 라벨링해서 **라벨러 간 일치율(kappa)** 을 같이 본다 — 사람끼리도 안 맞는 영역은 정답이 아니라 기준이 모호한 자리다.

## 절차

### 1. 영상 (제안)

| 축 | 값 | 영상 수 |
|---|---|---|
| 자세 | 좋음 / 나쁨(알려진 유형을 일부러 수행) | 각 12~16 |
| 카메라 각도 | 정면 / 측면 | 각 6~8 (자세와 교차) |
| 조명 | 밝음 / 어두움 | 일부 칸에 섞는다 |

촬영은 직접 하고 **촬영 대상의 동의**를 받는다(타인 영상 사용은 저작권·초상권 문제가 있다). 영상에는 정답이 «0회» 인 것(카메라 가림 등)도 한두 개 넣는다 — 측정 상태(`NO_POSE` 등)가 제대로 나오는지도 보인다.

### 2. 라벨링 — 사람 두 명이 따로

- **«나쁨» 의 기준은 영상을 보기 전에 서면으로 적는다**(예: 깊이 부족, 무릎 안쪽 쏠림). 기준을 AI 의 판정 기준에서 가져오면 «AI 가 맞는지» 를 AI 에게 묻는 꼴이 된다.
- 영상마다 실제 rep 수와 rep 별 좋음/나쁨을 적는다. 형식은 `ai-server/scripts/accuracy_samples/labels.example.csv`.

| 열 | 뜻 |
|---|---|
| `video_id` · `labeler` | 영상 식별자 · 라벨러(2명이 같은 영상을 따로) |
| `exercise` · `camera_angle` · `lighting` | 조건별 분해에 쓴다 |
| `true_rep_count` | 이 라벨러가 센 rep 수(영상 안에서 모든 행이 같아야 한다) |
| `rep_no` · `rep_label` | rep 번호(1부터) · `good` 또는 `bad`. 0회 영상은 한 행만 두고 둘을 비운다 |
| `bad_type` · `note` | 자유 기재(스크립트는 읽지 않는다) |

### 3. AI 결과 수집 — **자동 수집은 아직 없다**

같은 영상을 **실제 경로**로 돌려 결과를 `results.csv`(형식: `accuracy_samples/results.example.csv`)에 옮겨 적는다.

- **rep 수**: 측면 스쿼트는 `python scripts/evaluate_squat.py clip.mp4 --expected N` 의 JSON 에서 `reps` 를 쓴다(스트리밍 카운터를 오프라인으로 재생). 앱 경로로 돌렸다면 리포트의 총 횟수.
- **rep 별 좋음/나쁨**: 앱·Spring 경로의 리포트(`repTrend` 의 회차별 싱크로율)에서 옮긴다. **싱크로율을 좋음/나쁨으로 바꾸는 기준**(예: 정석 기준 미만 = 나쁨)은 라벨 기준과 별개로 **먼저 정해 적고 모든 영상에 같게 쓴다.** 이 변환이 정확도 수치에 영향을 주는 자유 변수라는 점을 보고서에 밝힐 것.
- rep 별 판정을 못 구했으면 `rep_no`·`ai_rep_label` 을 비워도 된다 — rep 수 지표만 나온다(그 영상은 rep 판정 비교에서 빠지고 보고서가 그 수를 알려 준다).
- `measured_status` 는 AI 가 측정하지 못한 영상을 가른다: `ok` 가 아니면(`no_person` · `no_rep` · `not_fully_visible` 등) «측정 못 한 영상» 에 따로 오른다.

### 4. 비교

```bash
cd ai-server
python scripts/accuracy_report.py --labels labels.csv --results results.csv --out report.md --json report.json
```

표준 라이브러리만 쓴다(설치 불필요). 입력 형식이 틀리면 파일·줄 번호와 함께 종료 코드 2 로 끝난다.

## 보고서 읽는 법

1. **rep 수**: 영상당 절대오차 평균(MAE)과 편향 — 양수면 AI 가 더 센다(과다 계수), 음수면 덜 센다.
2. **rep 별 판정**: 혼동행렬 + **재현율(나쁜 자세를 잡아내는가)** 과 정밀도. 이 앱에서는 나쁜 자세를 놓치는 쪽이 더 나쁘므로 재현율을 먼저 본다.
3. **라벨러 간 일치**: kappa 가 낮으면(사람끼리도 안 맞으면) AI 일치율을 해석할 수 없다 — 라벨 기준부터 다시 정한다.
4. **조건별**: 어떤 각도·조명에서 오차가 큰지. 베타 안내문(전신이 보이게, 밝은 곳, 측면 각도)의 근거가 된다.
5. **틀린 사례**: 숫자보다 이 목록이 보고서의 핵심이다.

결과가 나오면 README 의 «한계» 항목에 **숫자 한 줄**(구간·n 포함)을 올리고, 보고서·원본 CSV 는 `loadtest/results/` 와 같은 형태로 저장소에 남긴다(영상 자체는 올리지 않는다).

## 한계

- 스크립트는 **비교 계산**을 하는 도구이고, 라벨이 옳은지·영상이 대표성이 있는지는 보장하지 못한다.
- rep 번호를 1번부터 순서대로 맞춰 비교한다 — AI 가 rep 하나를 건너뛰면 그 뒤 번호가 전부 어긋나 판정 일치율이 과소평가될 수 있다(그 영상은 rep 수 오차로도 드러난다).
- 단위 시험의 기대값은 손으로 계산한 합성 데이터에서 나왔고(`ai-server/tests/test_accuracy_report.py`), **실제 영상으로 돌려 본 적은 없다.**
