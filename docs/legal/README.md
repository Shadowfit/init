# 법적 문서 초안 (처리방침·약관)

> 🔴 **초안이다 — 법률 검토 전이고, 게시·배포하지 않는다.** 이 문서들은 코드와 설정에서 **확인된 사실**을 모아 구조를 잡은 것이지
> 법률 자문이 아니다. 최종 문구는 개인정보보호위원회·KISA의 «개인정보 처리방침 작성지침» 양식과 필요하면 전문가 검토를 거쳐 정한다.
> 본문의 **`[확인 필요]`** 는 코드로 닫을 수 없는 항목(결정·법률·외부 사실)이다.

## 파일

| 파일 | 내용 | 동의 종류(`ConsentType`) |
|---|---|---|
| [`privacy-policy.md`](./privacy-policy.md) | 개인정보 처리방침 — 수집 항목·목적·보유 기간·위탁·국외 이전·권리 | `PRIVACY`, `HEALTH_INFO` |
| [`terms-of-service.md`](./terms-of-service.md) | 이용약관 | `TERMS` |

## 버전과 동의 기록

- 문서의 버전은 `application.yml` 의 `consent.version.terms | privacy | health-info` 다(현재 모두 `v1`).
- **문서를 개정하면 그 설정의 버전을 올린다.** 그러면 `GET /member/consents` 의 `missing` 에 다시 잡혀 앱이 재동의를 받는다.
  옛 버전에 대한 동의 기록은 지우지 않는다(`member_consents`, V36 — 언제 어떤 버전에 동의했는지가 기록의 목적).
- 서버가 동의를 **강제**하는 스위치는 `consent.enforce`(기본 꺼짐)다. 동의 화면이 있는 앱이 배포된 뒤에 켠다.

## 게시 전에 닫아야 하는 항목

코드 쪽에서 사실을 확인해 둔 것과 아직 비어 있는 것을 구분한다.

| # | 항목 | 상태 |
|---|---|---|
| 1 | 카메라 프레임을 서버가 디스크에 저장하는가 | **코드상 저장하지 않는다**(AI 서버 `/pose` 는 메모리에서만 디코딩, 파일 쓰기 없음). 단 앞단 nginx 가 큰 요청 본문을 임시 파일로 버퍼링할 수 있다(`proxy_request_buffering` 을 끄지 않았다) — 실제 임시 파일 처리 여부·삭제 시점은 `[확인 필요]` |
| 2 | Gemini 로 나가는 데이터 | **집계 숫자뿐이다**(이름·이메일·세션 id·키·몸무게 없음, `WeeklyReportPrompt` 문서 주석). 🔴 그러나 코드 주석(report-generation-llm.md §7 ③)이 «무료 티어는 입력이 학습에 쓰일 수 있다» 고 적어 둔다 — **유료 티어로 전환하거나 처리방침에 그대로 고지**해야 한다. `[결정 필요]` |
| 3 | 로그(접속 기록 등) 보존 범위 | 법정 보관 의무 확인 필요 (결정 D-6) |
| 4 | 국외 이전 | Google(Gemini)·Expo(푸시)·클라우드 리전 — 항목·시기·방법·목적·보유 기간을 법정 양식으로 `[확인 필요]` |
| 5 | 건강정보의 «민감정보» 해당 여부 | 키·몸무게·운동 수준. 해당하면 별도 동의 문구·안전성 조치가 달라진다 — `[법률 확인]` |
| 6 | 개인정보 보호책임자·문의 연락처 | `[미정]` |
| 7 | 만 14세 미만 | 가입을 제한하는 것으로 가정(법정대리인 동의 흐름은 만들지 않음) — `[확인 필요]` |
| 8 | 전송구간 암호화(HTTPS) | 운영 서버·도메인이 아직 없어 **현재 미적용**이다. 처리방침에 «적용한다» 고 쓰려면 운영 구성 후에 |
